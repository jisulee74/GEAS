8. 실무적 해석
==================================================

현재 코드에는 세 종류의 구현이 섞여 있다.

A. 문서에서 명시적으로 확인되는 구조
- module 3 저장/조회
- grid candidate -> feasible filtering -> cost evaluation
- no_data / limited / sufficient case 분기
- daily batch outer
- sensor correction 연결

B. 문서 취지를 반영한 구현
- 제약 기반 필터링 방향
- KPI 기반 정책 보정
- violation/robustness 기반 승인

C. 문서 비명시 정량 기준
- threshold 숫자
- candidate 간격
- batch 시각
- control_events 정의
- QC hyperparameter

문서 재현만이 목적이라면, C 항목은 코드에서 제거하기보다 먼저 "비명시 가정"으로 분리 관리하는 것이 바람직하다.
